# Durable mistake retention work note — 2026-09-13

This leaf implements S092 / INV-MIS-04 and the normalized persistence boundary. It is not a P4 gate report or evidence that App completion is integrated.

`course_mistake_encounter` records ordered, immutable graded target receipts. A receipt references the actual course/session/answer/target surface, exercise variant, pack hash, UTC instant and recorded local day. Negative replay indices are identities; a separate per-item sequence establishes chronology. Parent verdicts must be graded, and a new mistake origin must be a wrong parent with an actual wrong target. `course_mistake_state` is a checked cache whose current origin also joins that wrong attempt. Both tables belong to the course region and cascade only with course removal.

`SqliteMistakeStore` replays only the existing `core/session/mistakes.applyEncounter` rule to validate the cache: correct encounters in the creating session do not advance retirement; wrong encounters reset the streak; two correct encounters in other sessions retire the row. A later actual miss can start another lifecycle while prior receipts remain immutable. New rows require the real session machine's main-queue punitive `mistakeRows` evidence. The store never reviews an FSRS card or changes an achievement counter. Reviewer retirement and the account vocabulary union remain separately owned.

Existing live rows in the legacy `course_mistake` table are retained and reported as history requiring reconciliation; migration does not invent their concept, review streak or source proof. Invalid caches and receipt joins raise recoverable data errors without deleting rows. Completion will invoke this store with the same transaction-scoped Db after the actual scheduler has persisted parent/target receipts, so outer rollback covers both. The completed runtime wiring is a subsequent change.

Tests use real Node SQLite, the real session machine and the real scheduler for their encounter fixtures. They do not prove a production pack was signed, a native lesson rendered, or a human heard audio. Schema tests cover original source ownership, graded verdicts, immutable history, course cascade and interruption/retry. Store tests cover in-session replay, reset/retirement, retry, new lifecycle, legacy/corrupt preservation and rollback. The independent schema review's two invalid-parent counterexamples and the legitimate non-scorable accepted-answer positive control were reproduced and fixed before freeze. Accepted graded answers can retire an existing mistake, but cannot create one.
