# Durable lesson completion checkpoint

This checkpoint connects the real session machine and exact signed-item port to one SQLite completion transaction. It does not claim P4 or native device gates are green.

The runtime first saves the terminal session and immutable completion clock intent. A separate exclusive transaction applies each actual scheduler target once, saves chronological parent attempts and normalized child receipts, updates mistake retention and the declared destination node, then invokes the reviewed reward planner/writer. The same transaction-scoped database instance owns these stores. The reward writer owns global idempotency, the WordStore plan, day/economy updates and the frozen ceremony. Successful completion removes session staging; a failure preserves the original intent for explicit or foreground retry. Completion callbacks after dispatch are idempotent.

An untouched exit creates no attempt. Skip-only or otherwise ungraded histories preserve actual audit attempts but create no global committed session, reward, path progress or ceremony (INV-SESS-12 and INV-SESS-23). Their session identities cannot be reused. Genuine earlier-node due padding retains its original source and pool eligibility; only the declared destination progresses, and ordinary path padding does not spend either shared review entry-point pool.

MATCH keeps one parent Answer. Its immutable target receipts come from actual pair taps. Completion independently checks declared left-target order, canonical surfaces, paid-error/grade consistency and complete target coverage. Only the final failed grid that actually exhausts a finite allowance may contain fewer targets; untouched left items receive no encounter. Per-challenge raw taps remain a session-machine checkpoint detail; completed target receipts retain the observed semantic scheduling result.
