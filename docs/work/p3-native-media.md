# Native lesson media composition — 2026-09-13

This slice connects the existing Expo playback and speech-capture bindings to the existing single lesson media owner. It adds only `lessonAudioMode.ts`, `expoLessonMedia.ts`, their focused tests, and this evidence. It changes no dependency, native generated project, database/schema, App entry point, or shared lesson port.

`createExpoLessonMedia(bindings)` constructs an app-lifetime resource. Await `initialize()` to establish the explicit native idle policy, then await `prepare(locales)` at startup/pack activation/foreground before source generation or SQLite transactions. The latter refreshes actual installed TTS voices and local recognizer/permission facts without requesting permission. `canPlay(request)` and `canRecognize(locale)` are synchronous prepared-fact queries. Missing or failed recognizer probes remain unavailable for that exact requested locale.

Before displaying a changed challenge, await `activate({ normal, slow })` with the two explicit verified `LessonPlaybackRequest` tuples. Both must share item/text/locale, normal uses `slow:false`, and slow uses `slow:true` with its declared asset reference and `assetIsSlow` flag. Use `activate(null)` to disarm, including before preparation, after background, or after close. This stops the preceding source and publishes the exact current item's capabilities without starting playback or recording. Controls remain unavailable until the latest activation drains the old owner and refreshes the new request. Delayed requests for a different item/text/locale, another verified asset, or an undeclared slow/rate tuple are refused. Null activation never makes the resource foreground or prepared. Slow requests preserve the separately verified asset reference and `assetIsSlow` flag; the existing playback implementation owns the rate policy. Runtime generation uses `canPlay`/`canRecognize` before this display activation, so preparation does not depend on rendering a challenge.

The factory/native resource bridge must supply this explicit current-challenge activation hook. Its existing `FactoryResources.media` field alone does not perform that connection. No factory cast, unconditional availability fallback, or App switch is included here.

## Required providers

There are no defaults for these bindings:

- `resolveAudio(assetRef)` returns only the actual active verified repository's local URI. The existing playback driver refuses nonlocal URI schemes and uses its actual cached matching offline voice otherwise.
- `beforeLessonAudio()` durably persists and stops foreground Radio before any lesson cue, playback or capture acquires audio. A failed handoff reports unavailable through the existing owner; it does not start capture.
- `accessibility.read()/subscribe()/announce()` expose real screen-reader and announcement state. Unknown reads fail closed. The provider marks an announcement in flight before starting it and clears it from actual completion/interruption evidence. React Native's iOS-only `announcementFinished` event must not be replaced with an invented Android finish timer. Microphone activation remains explicit and is refused or interrupted while an announcement is in flight.
- `microphoneSignals.play('start'|'stop')` supplies the real start/stop earcon resource. Its `finished` promise reports actual completion; its idempotent `stop()` cancels/releases native resources without waiting for `finished`. It is independent of decorative Sound Effects, per INV-SND-02 / EC-A11Y-06. The provider owns actual cue assets and native signal rendering; this slice does not substitute a delay or silent mock. iOS ringer behavior and actual signal delivery still need integrated native verification.
- `remediate(cause)` opens the explicit S054/S055 action. Neither construction, initialization, activation, probing nor announcements call a permission request API.

Providers remain owned by the outer native factory. This resource owns the subscriptions and cue handles it obtains, not the provider's shared lifetime.

## Audio mode and cleanup

`LESSON_AUDIO_MODE_CONFIG` is a dated Freelingo implementation policy from deep/08 §12, not a claim about measured OS defaults. Idle playback respects silent mode and allows mixing. Foreground lesson speech uses the playback policy with silent-mode permission and exclusive interruption behavior. Neither mode permits background playback or recording. The new mode writer serializes all its writes and permits one lesson lease at a time.

Installed expo-audio 57.0.5 exposes `setAudioModeAsync(Partial<AudioMode>)`, but no getter for the current audio mode. The owner therefore establishes and restores a declared app baseline; it never invents a prior OS mode. Existing `speechCapture.ts` independently snapshots/restores the real iOS pre-microphone category/options around capture. All application audio-mode writes must use the same native resource ownership boundary; a second uncoordinated mode owner is unsupported.

`background()` immediately invalidates active requests and prepared facts, cancels pending cues and capture, then awaits the existing owner's drain. A delayed cue or locale probe cannot restart a backgrounded microphone. Foreground preparation never restarts capture. `close()` invalidates synchronously, unsubscribes, disposes the media owner and playback, and closes the mode writer. It attempts all cleanup after an error and reports aggregate failures. Partial native mode/release failures quarantine the resource instead of advertising usable media. Closed capability reads and stale callbacks never query disposed providers.

## Verification and limits

Twenty-eight focused checks pass (10 mode, 18 composition), with zero failures/skips. The composition tests use the actual `createLessonMediaOwner` and mode implementation with native-driver/provider doubles at the Expo boundary; they are not native device tests. They cover explicit initialization, per-locale cached preparation, exact slow request forwarding, microphone signal ordering, pending-cue background cancellation, source changes, stale probes, announcement interruption, failed/invalid observations, all-resource disposal and close during initialization.

The new disposed-provider regression first failed with three post-close reads, then passed after the closed-state guard. Independent review also reproduced enabled controls during pending cleanup and another verified asset accepted under the same item/text; those and three normal/slow source mismatch checks now pass. The bridge-driven null disarm regression also passed after its cleanup-only path was made safe. Five private Vite guard-removal transforms were killed by their unchanged tests: removing the closed-read guard performs three disposed reads; removing the source guard starts an old item's playback; removing post-cue cancellation starts a backgrounded microphone; removing activation-pending gating enables controls before native release; removing asset equality admits the wrong verified clip. Original source files were never changed by these mutations. Two read-only tests over the actual existing playback driver also pass: old voice success cannot replace a newer empty result, and an old rejection cannot erase newer valid voices. Those use exact native module aliases; the first private harness run had a module-identity `__DEV__` setup error, not an assertion failure. Initial missing-file collection failures and a sandbox cache-write startup failure are setup evidence, not behavioral failures. The first asynchronous interruption assertion was corrected to await the actual callback rather than a fixed number of promise turns.

The four-file TypeScript check, scoped ESLint and formatting checks pass. Exact test XML, mutation outcomes and hashes are under `p3-native-media-evidence/`; raw XML is losslessly compressed. No broad property suite was restarted during the host-pressure window. No simulator/emulator recording, native interruption/route test, ringer test, rendered recording-indicator check, or complete App factory run is claimed. Those integrated P3/P5 gates remain required.
